## Defects (ranked)

**D1 — Medium. `TIP_BIAS_MM = 0.2` is fit on the evaluation set with a non-robust statistic, and it makes accuracy slightly worse.** `vision.py:19-25`.
- It is the median signed error over all proposals on the same seed-1 darts it is then scored on. That pool includes fragment outliers of tens of mm. The developer's own robust figure (tips within 5 mm) is −0.10 mm, the opposite sign.
- Rerun with `--tip-bias 0`: exact scores are identical, and median tip error is *lower* (top 0.854 vs 0.931, left 0.865 vs 0.989, right 0.877 vs 0.999 mm).
- Effect on scores today is negligible, but it is test-set tuning. Fix: set it to 0.0 until it can be fit on held-out or real footage (M2-03).

**D2 — Medium (reporting). The doc and commit overstate "the tip rule works / is not the bottleneck".** `docs/M1-DETECTION-RESULTS.md:9,22`.
- Even with the optimistic union segmentation, ideal foot reaches only 90.5–94.5%, against a 99% gate. Fixing segmentation alone would not meet the gate. The limit is near-wire darts and roughly 1 mm tip error at the 1.7 px/mm warp (0.59 mm per warp pixel). The doc does say this in its "What limits it even here" paragraph, but the headline does not.
- "Only the tip median passes" is measured over the 19–28% of darts that got a proposal, which is a selection-biased statistic.
- Fix: reword the headline, and state that the ≥99% gate likely also needs sub-pixel or original-resolution tip refinement. This is a PM input.

**D3 — Medium (process). Browser suites overwrite committed evidence.**
- One `scripts/test.sh browser` run modified **46 tracked files in `qa-artifacts/`** (41 PNG, 5 JSON). That includes `presentation-results.json`, which is rewritten with the current failure. The suites write to hard-coded paths in 23 places under `tests/*.cjs`.
- Anyone who runs the suite and then does `git commit -a` silently replaces historical evidence. The developer worked around this by hand-restoring the files (`M1-01-baseline.json` notes).
- Fix: have the suites write to `process.env.DART_QA_ARTIFACTS || <root>/qa-artifacts`. Make `scripts/test.sh` default that variable to a gitignored `qa-artifacts/runs/<timestamp>/` (or a `mktemp -d`). Refresh committed evidence only with an explicit `--record`.

**D4 — Low. Stale pose after invalidation.** `vision.py:51-53`, `:290-291`.
- `invalidate()`, `reset_camera()` and a failed `align()` keep `pose`/`foot`, and `state()` still shows them while `aligned` is False. It is harmless today, because proposals need `aligned`, but the M1-04 UI indicator could show an outdated foot point.
- `mount_side` also persists across recalibration. That may be intended, but it should be documented.

**D5 — Low. PCA on simplified contour vertices.** `vision.py:215,245,257`.
- `CHAIN_APPROX_SIMPLE` returns only vertices, so the PCA axis and the "nearest pixel to the foot" for round blobs are computed on a sparse, uneven set. This was already the case before (the old rule did the same).
- Consider `CHAIN_APPROX_NONE` or the filled-mask pixels when segmentation is reworked.

**D6 — Low (test quality).**
- `tests/test_sim.py:78` is tautological (see M1-02). Adding the colour-vs-`score_point` pixel check as a unit test would guard against renderer regressions.
- `tests/test_pose.py:25`: the near-frontal distance check (<10%) passes only because the fallback HFOV (70°) equals the sim's HFOV.
- `TipRuleQA` uses two hand-picked darts. That is fine as a regression test, but not evidence.

**D7 — Low (code nits).**
- `tools/eval_detection.py:283`: the report hard-codes the camera settings (`1920/1080/70`) instead of reading them from the camera.
- `:139`: RNG streams are keyed by the mount's *index* in `MOUNTS`, so inserting a mount changes every later mount's darts. Key by name instead.
- `tools/diag_segmentation.py:90`: does not create the `--out` parent directory (`eval_detection.py:344` does).

Not defects: the harness re-bases per trial and uses exact calibration clicks in `ideal`, both as the plan specifies. There are no weakened thresholds: the pose test gates 5 mounts where the plan required 4, and the harness smoke test runs in under 30 s.
